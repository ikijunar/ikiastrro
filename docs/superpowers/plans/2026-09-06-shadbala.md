# PVR-first Shadbala and planetary-strength implementation plan

**Status:** Core implementation in progress; migration 39 is applied locally, planetary and Bhava fact persistence are in place. PVR dignity segments and Raman's Saptavargaja ladder are wired into Sthana Bala. Full calendrical precision, CLI verification, and UI remain.

## Goal

Implement one production strength calculation in Ikiastrro using the P.V.R. Integrated
Approach as the governing interpretation and rule profile. Use B. V. Raman's *Graha and
Bhava Balas* as the detailed computational reference because PVR explicitly refers readers
to Raman for the Shadbala formulas. Validate the result later against Jagannatha Hora and
record any differences as explicit convention corrections.

## Source policy

The application will not calculate two competing Raman/PVR strength totals. It will produce
one result under `PVR-Integrated-Strength`.

| Role | Source |
|---|---|
| Interpretation and use of strength | `SRC_PVR_INTEGRATED` |
| Detailed Shadbala formula reference | `SRC_RAMAN_GRAHA_BHAVA_BALAS` |
| Later external verification | `SRC_JHORA` and a saved JHora export |

PVR's chapter explains the six strength sources and when Shadbala, Ashtakavarga, Avastha,
and Vimsopaka should be used. It does not reproduce the full arithmetic, so Raman's detailed
formulae are a cited dependency of the PVR rule set rather than a second calculation mode.

### Dignity and relationship validation

The Saptavargaja calculation now uses the PVR Table 6 dignity segments (including the
Moon 0–3° Taurus and Mercury 0–15° Virgo boundaries, PVR node dignities, and each
Moolatrikona/own-sign split). Where PVR chapter 15 names the component but defers the
arithmetic, the implementation uses Raman's published ladder: Moolatrikona 45, own sign 30,
Adhimitra 22.5, Mitra 15, Sama 7.5, Shatru 3.75, and Adhishatru 1.875 shashtiamsas.
Dignity score and relationship score remain separate values; the relationship score is only
converted to Saptavargaja points for this component. This is covered by unit boundary tests and
the local Raman source registration `SRC_RAMAN_GRAHA_BHAVA_BALAS`.

## Scope

### First implementation

- Shadbala for Sun, Moon, Mars, Mercury, Jupiter, Venus, and Saturn.
- Six Bala families:
  - Sthana Bala
  - Dig Bala
  - Kala Bala
  - Cheshta Bala
  - Naisargika Bala
  - Drik Bala
- All documented subcomponents and intermediate values.
- Total virupas and rupas.
- Ishta Bala and Kashta Bala where the required inputs are available.
- Rule-set and formula-source provenance.
- Bhava Bala as a separate, explicitly named house-strength slice, not as a seventh
  planetary Bala.

### Deferred

- Vimsopaka Bala and Amsabala until the varga-weight conventions are reconciled.
- Ashtakavarga strength.
- A separate Rahu/Ketu Shadbala convention.
- Automatic changes to existing saved charts.

## Database design

The next migration is expected to be `39_add_shadbala_strength_facts.sql`, subject to the
current migration ledger when implementation starts.

### Rule layer

Use the existing `tbl_Rule_ShadbalaComponent` table and populate it under one immutable
strength rule set:

```text
RuleSetName = PVR-Integrated-Strength
SourceRefCode = SRC_PVR_INTEGRATED
FormulaSourceRefCode = SRC_RAMAN_GRAHA_BHAVA_BALAS
```

Seed rows for:

| Bala | Subcomponents |
|---|---|
| Sthana | Uchcha, Saptavargaja, Ojha-Yugma/Rasyamsa, Kendradi, Drekkana |
| Dig | Distance from the planet's full-direction house |
| Kala | Nathonnata, Paksha, Tribhaga, Varsha, Masa, Dina, Hora, Ayana, plus Yuddha adjustment where applicable |
| Cheshta | Motional/retrograde strength using the available astronomical inputs |
| Naisargika | Fixed natural-strength values for the seven classical planets |
| Drik | Benefic and malefic aspect contributions |

Each rule row must include its method code, maximum or scale, formula parameters, narrative,
source code, and any convention note needed for later JHora reconciliation.

Add a separate `tbl_Rule_BhavaBalaComponent` only if the existing generic strength rule row
cannot represent house-specific inputs cleanly. Bhava Bala must not be stored as a planet's
Shadbala component.

Register `SRC_RAMAN_GRAHA_BHAVA_BALAS` in the source catalogue with the edition used for the
local book. Do not create a second PVR source code for the same strength chapter.

### Fact layer

Create:

```text
tbl_Fact_PlanetaryStrength
tbl_Fact_PlanetaryStrengthComponent
tbl_Fact_BhavaStrength
tbl_Fact_BhavaStrengthComponent
```

The summary fact is one row per `ChartResultId + PlanetId` and stores the six Bala totals,
Shadbala total, virupas, rupas, Ishta/Kashta values, `RuleSetId`, and formula provenance.

The component fact is one row per `ChartResultId + PlanetId + BalaCode + SubComponentCode`
and stores the intermediate value, unit, input snapshot, rule row reference, and narrative.

The Bhava facts are one row per chart and house, with separate components for Bhavadhipati,
Bhava Dig, and Bhava Drik strength where supported by the selected method.

Add unique constraints and indexes around the chart result, planet, house, and component keys.
Facts must be append/version-safe: a changed rule set produces new facts after explicit
recalculation and never rewrites facts produced by an older rule set.

Bhava Bala now uses the three seeded components: Bhavadhipati Bala from the house lord's
Shadbala, Bhava Dig Bala from the sign-nature directional table, and Bhava Drik Bala from
benefic/malefic Sputa Drishti to the whole-sign house midpoint. It is stored independently
from planetary Shadbala and is materialised on the D1 chart result.

## Calculation architecture

Add a dedicated Core strength engine:

```text
src/Ikiastrro.Core/Engines/Strength/ShadbalaCalculator.cs
src/Ikiastrro.Core/Engines/Strength/BhavaBalaCalculator.cs
```

The calculators will consume the existing chart analysis inputs, including longitudes,
within-sign degrees, houses, aspects, retrograde state, birth time, sunrise/sunset, location,
and ayanamsa. They will return a calculation result containing the summary and component
rows before persistence.

The Data layer will add repositories for the strength rule rows and facts. The chart-generation
and analytic-recompute pipeline will persist and replace facts for one chart result only.

## Verification plan

Add a CLI verification mode:

```text
verify-shadbala
```

Verification will cover:

1. Unit cases for each Bala component.
2. Raman's standard horoscope and published intermediate examples where the values can be
   transcribed safely.
3. Existing Ikiastrro chart fixtures.
4. A later JHora export comparison.

Every discrepancy report must state whether the cause is:

- astronomical input precision
- house or Bhava-madhya convention
- day/night or calendrical convention
- retrograde/mean-motion convention
- rounding/truncation
- rule transcription
- an implementation defect

JHora differences will be corrected by a new versioned rule or convention row, never by
silently editing an already-used rule set.

## UI follow-up

- total Shadbala in rupas

- source/rule-set label: `PVR Integrated`

The first UI should expose the calculation trail, not only a single strength score.
